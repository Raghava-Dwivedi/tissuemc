| 2026-10-14 | `physics.hpp` `cross_or_not` (exit direction) | The engine's invariant check flagged 2.7 million of 4 million photons on V2 and 3.9 million on V3 as having a non-unit direction. | 2026-10-14 | `physics.hpp` `spin()` (direction norm) | 238 anomalies remained in 1.76e8 events, worst `abs(norm² - 1)` = 6.6e-9. First guess: the near-vertical branch. | A diagnostic run that recorded `abs(uz)` at every anomaly. The anomalies were at `abs(uz)` from 0.005 to 0.52, none near vertical, so the guess was wrong. | MCML's rotation formula uses `sqrt(1 - uz²)` where `sqrt(ux² + uy²)` would preserve length. For a slightly non-unit input the output error is multiplied by `cost² + sint²(1 + uz²)/(2(1 - uz²))`, averaged over azimuth; this exceeds 1 for `abs(uz)` above about 0.6, so the error grows. Harmless in float64, but float32 rounds about 1e9 times coarser. Direction is now renormalized after every spin. 0 anomalies in 1.76e8 events; a regression test runs 4e6 consecutive scatterings in float64 and float32. Checked afterwards with the renormalization removed from a scratch copy: float32 then violates the unit-direction invariant (`abs(norm² - 1)` above 1e-5) in 11,160,888 of 1.76e8 events (6.3%), against 0 with it, while the aggregate V2 reflectance is unchanged at six digits. So the effect is an invariant violation, not a measured bias in the results. |
