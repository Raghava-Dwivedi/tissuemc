Defects and surprises, recorded **as they happen** during the build. `VALIDATION.md` copies from this file. Entries are never reconstructed after the fact.

|---|---|---|---|---|
| 2026-10-13 | `tools/colab_smoke_test.ipynb` | The `ncu` check `rc == 0 and A or B` parsed as `(rc == 0 and A) or B`, which could report "WORKS" when `ncu` failed | Self-review before first use | Parenthesized the condition (commit `fix(tools): correct operator precedence in ncu check`) |
| 2026-10-14 | `tests/cpp/test_physics.cpp`: energy-conservation check | The check `Rsp + (Rd + Tt + A) / N == 1` failed at 1e6 photons with a plain `double` accumulator (tolerance 2e-12). Measured deviation: 3e-14 at 1e4 photons, 7e-13 at 1e5, 5.7e-12 at 1e6, growing with N. | Failed test. Checked first whether this was a real weight leak (a leak would be a fixed offset) or rounding: re-ran with Neumaier compensated summation and the deviation was exactly 0 at 1e4, 1e5, 1e6 and 4e6 photons. | Physics is correct. Added `include/tissuemc/accumulate.hpp` (`CompensatedSum`) and use it for tallies. Tolerance tightened to 1e-13, which the old accumulator would fail, so the test now discriminates. |
| 2026-10-14 | `physics.hpp` `cross_or_not` (exit direction) | The engine's invariant check flagged 2.7 million of 4 million photons on V2 and 3.9 million on V3 as having a non-unit direction. V1, whose photons never refract out, was clean. | The engine's own anomaly counter (non-finite weight or direction norm off by more than 1e-9, checked at every scoring call). | A photon leaving through a refracting boundary had its `uz` updated but not `ux`, `uy`, so the exit direction was not a unit vector. MCML does the same (it only uses `uz` there). Lateral components are now scaled by `ni/nt` too. Anomalies fell to 238 (V2) and 529 (V3); the physics results did not change. |
| 2026-10-14 | `physics.hpp` `spin()` (direction norm) | 238 anomalies remained in 1.76e8 events, worst `abs(norm² - 1)` = 6.6e-9. First guess: the near-vertical branch. | A diagnostic run that recorded `abs(uz)` at every anomaly. The anomalies were at `abs(uz)` from 0.005 to 0.52, none near vertical, so the guess was wrong. | MCML's rotation formula uses `sqrt(1 - uz²)` where `sqrt(ux² + uy²)` would preserve length. For a slightly non-unit input the output error is multiplied by `cost² + sint²(1 + uz²)/(2(1 - uz²))`, averaged over azimuth; this exceeds 1 for `abs(uz)` above about 0.6, so the error grows. Harmless in float64, but float32 rounds about 1e9 times coarser. Direction is now renormalized after every spin. 0 anomalies in 1.76e8 events; a regression test runs 4e6 consecutive scatterings in float64 and float32. |
| 2026-10-14 | V2 reference values | Engine diffuse reflectance 0.2199 against a published 0.2600; the gap equals the specular reflectance, 0.04. | Computed the answer from first principles with Chandrasekhar's H-function (`oracle.py`, no shared code with the engine): 0.219704 diffuse, 0.259704 total. Engine: 0.219857 ± 0.000144 (z = +1.06). The MCML manual defines its Rd as excluding specular. | The engine was right. The three values in Table 6.2 correspond to total reflectance (diffuse + specular), while Tables 6.1 and 6.7 are diffuse-only. `references.json` and `DESIGN.md` now say so, with the evidence. The oracle also gives a matched-boundary case (O1) that depends on no published table: 0.414947, engine 0.414880 ± 0.000185. |
| 2026-10-14 | V3 transmittance (**open**) | Engine T_t = 0.09599 ± 0.00003 over 8 seeds and 3.2e7 photons, against published 0.0965 (MCML, 1e6 photons) and 0.0974 (Gardner, 1e5). It passes the pre-set marginal rule |z| < 3, but at z between −2.1 and −2.9 across seeds. Rd agrees (z within ±1.7) and so does Rd + Tt for MCML. | The validation suite. Chance in the old published runs is plausible but unproven. To resolve it: run the original `mcml.c` on the same input at high photon count (milestone M4, which needs approval for the download). |
