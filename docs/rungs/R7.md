# Rung R7: the depth and radius profiles in shared memory

The planned privatization rung (called R2 in the design), applied on top of R6 because of what the diagnostic showed: with the depth and radius profile atomics removed, R6 took 0.823 s instead of 10.053 s, so those atomics were 92% of its run time (see [`LOG.md`](../../LOG.md)).

## What changes from R6

Every absorption event adds to the depth profile `A(z)` with a global atomic. The benchmark's profile has 40 bins (320 bytes, about three cache lines), so about 6×10⁹ adds serialized on the same few lines at one part of L2. R7 keeps the profiles but stops sending those adds there:

- **One private copy of both profiles per warp, in shared memory.** The depth profile (40 bins) and the radius profile (50 bins) are 720 bytes in `double`; four warps per block make 2.9 KB. A lane's adds now contend only with the other lanes of its own warp, and never leave the multiprocessor.
- **One flush at the end.** When the block's lanes have run out of photons, one thread per bin sums the block's copies and makes a single global add. That is 90 global adds per block instead of billions.
- **The accumulators are `double`**, the tally's precision. A float total in shared memory would lose small additions exactly as a global one does (the float demonstration in R0).

Everything else is R6: persistent lanes, state in registers, the same photons, the same random numbers, the same scoring of R_d, T_t and absorbed weight. The per-photon atomics on those (about 6 per photon) are untouched; they are about 2×10⁷ against 6×10⁹.

## Why it is correct

- R7 with one lane is R6 bit for bit, in host emulation: the single copy receives the adds in R6's order and is added to zeros.
- With many lanes in groups, advanced round-robin and shuffled, the totals, absorbed weight and counts are identical to R6's and the profiles agree to double rounding per bin (the summation order differs). The shared photon counter still ends at `photons + lanes`.
- The profiles agree with the CPU engine as the earlier rungs' did: totals to 1e-6 and bins to a part in a thousand.
- Breaking the flush (leaving a group out) fails all three of these tests.
- On the GPU, `tissuemc-cross-engine` now compares the profiles themselves against the CPU on identical photons, which no earlier GPU check did. Its limits were fixed before the first run of R7.

## What it depends on

The cost it removes comes from many adds landing on a few cache lines, which is a property of this benchmark's coarse depth profile (40 bins of 0.01 cm). With a finer profile the global adds would spread over more lines and the benefit would be smaller; that was not measured, and only this benchmark's number is claimed.

## What is measured

Validation (24 checks), the comparison with the CPU including the profiles, and throughput with **R6 run before and again after** in the same session, and the **diagnostic** (R6 without the profiles) beside them as the target: R7 keeps the profiles, so it cannot be faster than the diagnostic, and how close it gets is the result. Counters for R7 and the diagnostic show what is left.

## What would count as a surprise

Shared-memory adds of `double` are compare-and-swap loops on this architecture, and lanes of one warp that add to the same bin retry against each other. If R7 is much slower than the diagnostic, the counters should show it as shared-memory or branch waiting, and the next change is to reduce the contention inside the warp (combine lanes with the same bin before adding). If R7 is close to the diagnostic, the atomics are solved and the next limit is something else.

## Outcome

Validated (24 of 24), with the depth and radius profiles agreeing with the CPU to about 10⁻⁶ (limits 10⁻⁴ and 10⁻³). R7 took 1.961 s against R6's 10.052 s (5.1× faster, 5.0× on the repeat) for the same events, closing 88% of the gap to the profiles-off diagnostic (0.850 s). What remains is not yet attributed; the notebook's counters compare R7 with the diagnostic. Numbers and the reading are in [`LOG.md`](../../LOG.md) and the README.
